# Прямой доступ к Telegram Bot API

Статус: принято.

## Контекст

Приложение работает на Spring Boot 4 и Jackson 3. Популярная Java-библиотека
TelegramBots на момент принятия решения ещё не завершила переход со Spring Boot
3 на Spring Boot 4 и может добавить в приложение несовместимые зависимости
Jackson 2.

Бот сначала запускается локально вместе с веб-приложением. Для такого режима
не нужен публичный HTTPS-адрес: обновления можно получать через long polling.

## Решение

Telegram-адаптер обращается к официальному Bot API напрямую через Spring
`RestClient`, который уже входит в зависимости приложения. Получение обновлений
выполняется через `getUpdates`, а жизненный цикл фонового опроса управляется
Spring `SmartLifecycle`.

Бот выключен по умолчанию. Токен и список разрешённых Telegram-пользователей
передаются только через переменные окружения.

## Альтернативы

- `telegrambots-springboot-longpolling-starter` не выбран из-за незавершённой
  совместимости со Spring Boot 4 и Jackson 3.
- Webhook не выбран для локального этапа, потому что требует доступного из
  интернета HTTPS-адреса. К нему можно вернуться при публичном размещении.
- Отдельный сервис для бота не выбран: текущий модульный монолит уже содержит
  бизнес-сервисы, которые должен переиспользовать Telegram-адаптер.

## Последствия

- новая Maven-зависимость не требуется;
- форматы запросов и ответов Telegram описываются внутри модуля `telegram`;
- обновление версии Bot API может потребовать изменения собственного клиента;
- при публичном развёртывании long polling можно заменить webhook-адаптером без
  переноса бизнес-логики.
