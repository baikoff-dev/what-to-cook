# Архитектурные решения

В этой папке хранятся ADR (Architecture Decision Records) — короткие записи о
значимых технических решениях и причинах их принятия.

ADR нужен, если решение:

- заметно влияет на архитектуру или несколько функциональных областей;
- создаёт долгосрочное ограничение;
- имеет несколько разумных альтернатив;
- с высокой вероятностью вызовет в будущем вопрос «почему сделано именно так?».

Мелкие рефакторинги, названия методов и детали одной реализации ADR не требуют.

## Формат

Файлы нумеруются последовательно:

```text
0001-краткое-название.md
0002-следующее-решение.md
```

Рекомендуемая структура записи:

```markdown
# Название решения

Статус: предложено | принято | заменено

## Контекст

Какую проблему решаем и какие ограничения учитываем.

## Решение

Что выбрано.

## Альтернативы

Какие варианты рассматривались и почему не выбраны.

## Последствия

Какие преимущества, ограничения и дальнейшие действия появляются.
```

ADR создаётся при принятии решения, а не как журнал уже написанного кода. Если
решение меняется, старая запись сохраняется, а новая ссылается на неё и получает
статус «заменено».
