# Что приготовить?

Локальный помощник для хранения и подбора рецептов с учётом имеющихся
продуктов, оборудования и личных ограничений.

Английское рабочее название: **What to Cook?**

GitHub-репозиторий:
<https://github.com/baikoff-dev/what-to-cook>.

## Текущий статус

Реализованы каталог, карточка и управление рецептами. Рецепты можно создавать,
редактировать, перемещать в архив и восстанавливать. Поддерживаются основное
изображение блюда и изображения отдельных шагов. Чистая база содержит три
демонстрационных личных рецепта и двенадцать классических блюд со статусом
`UNTESTED`.

На карточке рецепта можно выбрать другое количество порций: ингредиенты пересчитываются
без изменения исходного рецепта. При ошибках создания или редактирования форма показывает
общую сводку, выделяет проблемные поля и переводит к первой ошибке.

В каталоге доступны поиск по русскому и английскому названию, а также по ингредиентам.
Результаты можно отфильтровать по времени, сложности, оборудованию и способу приготовления.
На отдельной странице можно отметить имеющиеся продукты, увидеть процент совпадения каждого
рецепта и список недостающих обязательных ингредиентов.

Начат Telegram-интерфейс приложения. При локальном запуске бот получает
обновления через long polling, ограничивает доступ списком Telegram ID,
отвечает на команду `/start`, предлагает случайный рецепт и подбирает блюда по
перечисленным пользователем продуктам.

В каталоге `frontend` развивается отдельное React-приложение. Оно получает
каталог, варианты фильтров и подробности рецепта через REST API, позволяет
искать рецепты, открывать их клиентские страницы и пересчитывать ингредиенты
для выбранного количества порций. На странице рецепта его можно добавить в
избранное или удалить оттуда без перезагрузки. Отдельная React-страница
избранного показывает сохранённые карточки и позволяет сразу убрать ненужную.
В React также перенесены форма отметки приготовления и история с оценками,
заметками и удалением ошибочных записей. Рецепт можно перенести в архив из его
карточки, просмотреть на отдельной React-странице и восстановить. Переход
выполняется без переписывания бизнес-логики backend. Создание и редактирование
рецепта также выполняются в React: форма поддерживает ингредиенты, допустимые
замены, шаги, оборудование и источники. При редактировании обложку можно
заменить с предпросмотром или пометить на удаление. Замена и удаление
выполняются только после сохранения формы. Для каждого шага можно выбрать новое
изображение JPEG или PNG, увидеть предпросмотр либо пометить существующее
изображение на удаление. Такое действие можно отменить до сохранения рецепта.
Ссылка «Ограничения» открывает отдельную React-страницу с действующими правилами,
их режимами и личными заметками. На этой же странице можно добавить, изменить
или удалить правило; при редактировании ингредиент остаётся неизменяемым, а
удаление требует отдельного подтверждения.

[техническом задании](docs/technical-specification.md).

## Запуск PostgreSQL

```powershell
docker compose up -d
docker compose ps
```

Контейнер считается готовым, когда сервис `postgres` перешёл в состояние
`healthy`. Данные сохраняются в именованном Docker volume и не пропадают после
обычной остановки контейнера.

Полезные команды:

```powershell
docker compose logs postgres
docker compose stop
```

Команда `docker compose down --volumes` удаляет локальные данные и не должна
выполняться без явного решения об их удалении.

## Запуск приложения в Windows

Сначала запусти PostgreSQL, затем приложение:

```powershell
.\mvnw.cmd spring-boot:run
```

После запуска приложение доступно по адресу <http://localhost:8080>.

Основные страницы:

- главная: <http://localhost:8080>;
- каталог: <http://localhost:8080/recipes>;
- создание рецепта: <http://localhost:8080/recipes/new>;
- архив: <http://localhost:8080/recipes/archive>;
- базовая кладовая: <http://localhost:8080/preferences/pantry>;
- карточка рецепта: `/recipes/{id}`.

## Запуск нового frontend в Windows

Backend и PostgreSQL должны быть запущены командами из предыдущих разделов.
Во втором терминале выполни:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

React-клиент с каталогом доступен по адресу <http://localhost:5173>. Карточка
рецепта открывается по адресу `/recipes/{id}`, создание — `/recipes/new`, а
редактирование — `/recipes/{id}/edit` в том же клиенте. Запросы к
`/api`, `/images` и `/user-images` Vite проксирует на
<http://localhost:8080>, поэтому локальная разработка не требует отдельной
настройки CORS. Каталог загружается методом `GET /api/recipes`, а справочники
для формы — методом `GET /api/recipes/filter-options`. Подробности и
пересчитанные ингредиенты возвращает
`GET /api/recipes/{id}?servings={количество}`. Управление рецептом использует
`GET /api/recipes/form-options`, `GET /api/recipes/{id}/edit`,
`POST /api/recipes` и `PUT /api/recipes/{id}`. Ссылки на ещё не перенесённые
действия используют `VITE_BACKEND_URL`; локальное значение по умолчанию —
`http://localhost:8080`. Избранное изменяют идемпотентные методы
`PUT /api/recipes/{id}/favorite` и `DELETE /api/recipes/{id}/favorite`, а список
возвращает `GET /api/recipes/favorites`. Приготовление сохраняет
`POST /api/recipes/{id}/cookings`, историю возвращает
`GET /api/cooking-history`, а запись удаляет
`DELETE /api/cooking-history/{recordId}`. Клиентские страницы доступны по
адресам `/recipes/{id}/cookings/new` и `/recipes/history`.
Архив возвращает `GET /api/recipes/archive`, рецепт переносится туда методом
`PUT /api/recipes/{id}/archive` и восстанавливается методом `DELETE` по тому же
адресу. Клиентский маршрут архива — `/recipes/archive`.

`npm.cmd` используется вместо `npm`, потому что PowerShell на некоторых
установках Windows блокирует выполнение скрипта `npm.ps1`.

## Запуск Telegram-бота

По умолчанию бот выключен и не влияет на обычный запуск веб-приложения. Для
включения создай бота через `@BotFather`, не публикуй полученный токен и задай
переменные окружения в текущем окне PowerShell:

```powershell
$env:TELEGRAM_BOT_ENABLED="true"
$env:TELEGRAM_BOT_TOKEN="токен-от-BotFather"
$env:TELEGRAM_ALLOWED_USER_IDS="123456789"
.\mvnw.cmd spring-boot:run
```

Несколько разрешённых ID перечисляются через запятую. Токен нельзя добавлять в
Git, `application.yaml` или сообщения об ошибках. Файл `.env.example` показывает
названия настроек, но Spring Boot не загружает его автоматически.

Команда `/start` показывает начальное меню. Кнопка «Удиви меня» выбирает один
рецепт через общий сервис рекомендаций и присылает название, описание, время,
сложность и предупреждения об ограничениях. Кнопка
«Удиви ещё раз» запускает новый выбор.

Кнопка «Подобрать по продуктам» переводит бота в режим ожидания списка.
Продукты вводятся русскими названиями через запятую, без учёта регистра,
лишних пробелов и различия `е/ё`. Название `лук` считается короткой формой
`Репчатый лук`. Если продукт отсутствует в справочнике, бот сообщает его
название и ждёт исправленный полный список. Для подходящего блюда показываются
процент совпадения и недостающие продукты. Кнопка «Другой вариант» перебирает
до трёх результатов текущей подборки, а «Изменить продукты» начинает ввод
заново.

Состояние Telegram-диалога хранится только в памяти процесса и сбрасывается при
перезапуске приложения. Если у выбранного рецепта есть доступная обложка, бот
загружает её в Telegram как фотографию и помещает описание рецепта в подпись.
Поддерживаются как встроенные обложки, так и изображения, загруженные
пользователем. Если файл отсутствует или не читается, бот отправляет обычное
текстовое сообщение, поэтому рекомендация всё равно остаётся доступной.

## Каталог рецептов

Модель каталога хранит отдельно рецепты, ингредиенты, шаги, оборудование и
способы приготовления. Связь рецепта с ингредиентом содержит точное количество,
единицу измерения, порядок отображения и признак необязательного продукта.

Начальные справочники и три демонстрационных рецепта создаются миграцией
`V2__recipe_catalog.sql`. Изменять уже применённую миграцию нельзя: дальнейшие
изменения схемы и данных выполняются новыми миграциями.

## Управление рецептами

Форма создания и редактирования поддерживает динамические списки ингредиентов и
шагов. Новый ингредиент создаётся автоматически, если в справочнике ещё нет
названия без учёта регистра. Для рецепта обязательны хотя бы один ингредиент,
один шаг, оборудование и способ приготовления.

К рецепту можно добавить необязательную ссылку на видео приготовления. Она
хранится отдельно от ссылки на текстовый источник и показывается в карточке
рецепта с открытием исходного сайта в новой вкладке.

Рецепты не удаляются безвозвратно. Архивный рецепт скрывается из основного
каталога, но остаётся в базе и доступен на React-странице архива. После
восстановления без перезагрузки рецепт получает тот статус проверки, который
был у него до архивации.

## Изображения

Разрешены JPEG и PNG размером не больше 5 МБ и со стороной не больше 8000
пикселей. Загруженные пользователем файлы хранятся локально в
`data/images/recipes/{recipeId}/`, а база содержит только относительные пути.
Каталог `data/images` исключён из Git.

Встроенные обложки поставляются вместе с приложением в каталоге
`src/main/resources/static/images`. Их пути в базе начинаются с `bundled:` и
преобразуются в публичные адреса `/images/...`. При замене такой обложки
пользовательским файлом встроенный ресурс остаётся в составе приложения.

Фотографические встроенные обложки сохраняются как JPEG размером 1200×800
пикселей с качеством около 85%. Рекомендуемый размер одного файла — не больше
500 КБ: этого достаточно для карточки рецепта и подробной страницы без
излишней нагрузки на каталог.
Все 12 классических рецептов поставляются со встроенными обложками.

Папку хранения можно переопределить переменной окружения `IMAGES_DIRECTORY`.
При замене изображения новый файл сначала сохраняется и проверяется, а старый
удаляется только после успешной фиксации изменений рецепта в базе.
React-форма редактирования принимает новую обложку в формате JPEG или PNG
размером до 5 МБ и отправляет её вместе с JSON рецепта как `multipart/form-data`.
Удаление обложки сначала отмечается только в интерфейсе и передаётся флагом
`removeMainImage` в JSON при сохранении. Файл удаляется после успешной фиксации
изменений рецепта, а действие можно отменить до отправки формы.
Изображения шагов отправляются в том же multipart-запросе: JSON-массив
`stepImageIndexes` сопоставляет повторяющиеся части `stepImages` с порядковыми
номерами шагов. Для удаления шага React передаёт `removeImage: true` в JSON.
Замена и удаление используют ту же транзакционную защиту: старый файл удаляется
только после успешной фиксации изменений, а новый файл отменяет отметку об
удалении для соответствующего шага.

## Пересчёт порций

Карточка рецепта принимает выбранное количество порций через параметр `servings`, например
`/recipes/1?servings=4`. Количество каждого ингредиента пересчитывается относительно базового
числа порций и округляется максимум до трёх знаков после запятой. Единицы измерения при этом
не преобразуются, а сохранённые в базе значения не изменяются.

## Поиск и фильтры

Поиск и фильтры передаются параметрами страницы каталога или REST API. Например:
`/recipes?query=курица&maxMinutes=60&difficulty=EASY` и
`/api/recipes?query=курица&maxMinutes=60&difficulty=EASY`. Поиск выполняется по части русского
или английского названия рецепта и ингредиента без учёта регистра. Фильтры можно совмещать:
рецепт должен одновременно соответствовать всем выбранным условиям.

## Подбор по продуктам

Страница `/recipes/match` позволяет выбрать продукты из справочника. Для каждого активного
рецепта рассчитывается доля имеющихся обязательных ингредиентов. Количество продукта пока
не учитывается, а необязательные ингредиенты не влияют на процент и список недостающего.
Результаты сортируются по проценту совпадения, количеству недостающих продуктов, времени и
названию. Рецепты без совпадений по обязательным ингредиентам не показываются.

Допустимая замена полностью удовлетворяет соответствующий обязательный ингредиент. Если выбраны
и основной продукт, и его замена, ингредиент учитывается один раз с приоритетом основного продукта.
Для использованной замены подбор показывает исходный и выбранный продукты, тип замены и её влияние
на результат. Те же правила расчёта использует помощник выбора блюда.

Страница `/preferences/pantry` хранит продукты, которые почти всегда есть дома. На чистой базе
это вода, растительное масло и соль. Состав можно изменить; выбранные продукты автоматически
добавляются к отмеченным вручную при расчёте процента в подборе и помощнике. Карточка результата
отдельно показывает, какие ингредиенты были взяты из базовой кладовой. Сама кладовая без хотя бы
одного выбранного пользователем продукта не запускает подбор.

## Избранные рецепты

Рецепт можно добавить в избранное из каталога или с его страницы. Все отмеченные блюда
доступны на странице `/recipes/favorites`. Повторное нажатие снимает отметку.

Избранное хранится отдельно от рецептов. При переносе рецепта в архив отметка сохраняется,
но сам рецепт временно скрывается из избранного. После восстановления он снова появляется
в списке.

## История приготовления

На странице рецепта можно отметить очередное приготовление блюда. Для каждой записи отдельно
сохраняются дата, необязательная оценка от 1 до 5 и заметка. Все записи доступны на странице
`/recipes/history` в React-клиенте и сортируются от новых к старым. Создание и удаление
выполняются через REST API без перезагрузки страницы.

История сохраняется при переносе рецепта в архив. Архивный рецепт остаётся в списке с пометкой,
но ссылка на его обычную страницу скрывается. Ошибочную запись истории можно удалить.

## Ограничения по ингредиентам

На странице `/preferences/restrictions` можно назначить ингредиенту один из двух режимов:

- `WARN` — оставить рецепт в результатах и показать заметное предупреждение;
- `EXCLUDE` — скрыть рецепт из каталога, избранного и подбора по продуктам.

Ограничение срабатывает при любом присутствии ингредиента, в том числе необязательного.
Прямая страница исключённого рецепта остаётся доступной и объясняет, какие правила сработали.
Правило относится к точному ингредиенту из справочника и автоматически не распространяется
на похожие продукты. Личная заметка отображается рядом с предупреждением.

Личные ограничения оцениваются по составу самого рецепта. Выбор допустимой замены при подборе
не отменяет ограничение, назначенное исходному ингредиенту рецепта.

Приложение выполняет заданные правила, но не определяет медицински безопасную частоту
употребления продуктов.

React-клиент получает список правил и справочники через
`GET /api/ingredient-restrictions`, а новое правило сохраняет через
`PUT /api/ingredient-restrictions/{ingredientId}`. После сохранения список и
счётчик обновляются без перезагрузки страницы. Этот же endpoint обновляет режим
и заметку существующего правила. Правило удаляется через
`DELETE /api/ingredient-restrictions/{ingredientId}` после явного подтверждения
в карточке; список и счётчик также обновляются без перезагрузки.

## Помощник выбора блюда

Страница `/assistant` помогает выбрать блюдо без просмотра всего каталога. Можно указать продукты,
максимальное время, доступное оборудование, способ приготовления и допустимую сложность либо нажать
«Не знаю, предложи сам». Помощник показывает до трёх вариантов и для каждого объясняет выбор,
указывает недостающие продукты и учитывает историю приготовления.

В режиме «Не знаю, предложи сам» варианты выбираются случайно при каждом запросе. Сначала помощник
предлагает блюда, которые ещё не отмечались приготовленными, а если их меньше трёх — заполняет
оставшиеся места случайными блюдами из истории. Архивные рецепты и рецепты, исключённые личными
ограничениями, в подборку не попадают.

Цель выбора меняет порядок подходящих вариантов:

- «Использовать имеющиеся продукты» ставит выше рецепты с лучшим совпадением;
- «Приготовить побыстрее» отдаёт приоритет общему времени;
- «Попробовать новое» учитывает, готовилось ли блюдо и как давно;
- «Выбрать любимое» использует избранное и среднюю оценку из истории;
- «Без разницы» сочетает совпадение продуктов, давность и время.

Время, оборудование, способ приготовления и максимальная сложность работают как фильтры: рецепт,
который им не соответствует, не участвует в дальнейшем ранжировании.

Рецепты с режимом ограничения `EXCLUDE` и рецепты из архива в рекомендации не попадают.
Если подходит несколько блюд, выше оказываются варианты с большим совпадением продуктов, а затем —
те, которые ещё не готовились или готовились давно. Это обычный алгоритм на данных приложения:
он не генерирует новые рецепты и не обращается к внешнему ИИ-сервису.

## Начальный каталог

В чистой базе создаются 15 рецептов: три демонстрационных личных рецепта и двенадцать
классических блюд из выбранных кухонь. Классические рецепты имеют точные количества продуктов,
оборудование, способы приготовления, пошаговое описание и ссылку на использованный источник.
Их тексты адаптированы для приложения и не копируют исходные публикации дословно.

Все классические блюда изначально помечены как «Не проверен». После приготовления статус,
количества и заметки можно уточнить через редактирование. Для части ингредиентов указаны допустимые
замены с пояснением, насколько они изменяют результат. Все двенадцать классических блюд
поставляются со встроенными обложками.

Начальный каталог добавляется миграцией `V8__seed_classic_recipes.sql`. Миграция
`V9__audit_classic_recipes_against_sources.sql` приводит ингредиенты, пропорции и технику всех
двенадцати классических блюд в соответствие с указанными в карточках источниками. Если источник
не задаёт точное количество продукта для жарки или приправы, в приложении указано рабочее
нормализованное количество, а не расплывчатое «по вкусу».

Для сохранения исходных пропорций в справочник единиц добавлен `CUP` («стакан»). Предлагаемые
замены оставлены только там, где их прямо допускает источник: например, сухой херес или мирин
вместо шаосинского вина и нейтральное растительное масло вместо арахисового.

## Тесты в Windows

```powershell
.\mvnw.cmd test
```

Тесты используют собственный временный PostgreSQL через Testcontainers. Для
их запуска Docker Desktop должен работать, но вручную запускать `compose.yaml`
не требуется.

Новые функции разрабатываются по Outside-In TDD: сначала согласовывается
пользовательский сценарий и создаётся падающий acceptance-тест, затем появляется
минимальная реализация и выполняется рефакторинг. Подробный процесс описан в
[стратегии тестирования](docs/testing-strategy.md).

Проверки нового frontend запускаются отдельно:

```powershell
cd frontend
npm.cmd run lint
npm.cmd run test
npm.cmd run build
```

## Конфигурация базы

Локальные значения по умолчанию:

```text
Database: what_to_cook
Username: what_to_cook
Password: what_to_cook
URL: jdbc:postgresql://localhost:5432/what_to_cook
```

Переопределить их можно переменными `DB_URL`, `DB_USERNAME` и `DB_PASSWORD`.
Пример переменных находится в `.env.example`.

Схема базы изменяется только миграциями из
`src/main/resources/db/migration`. Hibernate настроен на проверку схемы и не
создаёт таблицы автоматически.
